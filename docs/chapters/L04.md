# L04 可重現研究：版本控制、環境紀錄與 AI 程式碼審查

## 學習目標

- 用 Git 記錄每一個分析步驟，必要時回到前一版。
- 把專案推送到 GitHub，作為作業繳交與研究紀錄。
- 記錄軟體版本，讓別人（包括半年後的自己）能重現結果。
- 用固定清單審查 AI 寫的程式碼。

## 時間配置

| 段落 | 時間 | 內容 |
|---|---|---|
| 觀念 | 15 分鐘 | 為什麼研究程式要版本控制 |
| 實作 | 30 分鐘 | init、commit、push；寫環境紀錄 |
| 審查練習 | 15 分鐘 | 用審查清單檢查一段 AI 程式碼 |

## 1. 為什麼研究程式要版本控制

GWAS 流程有十幾個步驟，任何一步改了參數，後面的結果都會變。沒有版本控制，就很難回答審稿人「你的 QC 閾值是多少、改過幾次」。Git 讓每次修改都留下紀錄與說明。

## 2. Git 的最小指令集

```bash
cd ~/vibegwas
git init                       # 讓這個資料夾開始被 Git 追蹤
git add scripts/ CLAUDE.md     # 選擇要記錄的檔案
git commit -m "新增表現型計數腳本"  # 存一個版本，附上說明
git log --oneline              # 看歷史紀錄
```

!!! warning "不要把資料放進 Git"
    基因型檔案很大，也可能含受試者資訊。請在專案根目錄建立 `.gitignore`：

    ```text
    data/
    results/
    *.bed
    *.bim
    *.fam
    ```

    Git 只記錄**腳本與說明**，資料與結果可以由腳本重新產生。

## 3. 推送到 GitHub

1. 在 GitHub 網站建立一個新的 repository（例如 `vibegwas-homework`）。
2. 依 GitHub 畫面指示連結並推送，或請 AI 幫忙：

```text
我已經在 GitHub 建立了空的 repo，網址是 https://github.com/<我的帳號>/vibegwas-homework。
請告訴我把目前資料夾推送上去的指令，一步一步來，每一步我執行後回報結果。
請先確認 .gitignore 已經排除 data/ 和 results/。
```

## 4. 記錄軟體版本

在 `scripts/00_versions.sh` 寫入：

```bash
#!/bin/bash
{
  date
  plink --version
  plink2 --version
  python3 --version
} > results/software_versions.txt 2>&1
```

每次正式分析前執行一次。論文方法學要寫出軟體版本，這份檔案就是依據。

## 5. AI 程式碼審查清單

每次 AI 給你一段程式，執行前逐項檢查：

| 檢查項目 | 要問自己的問題 |
|---|---|
| 輸入檔 | 讀的是正確的檔案嗎？路徑對嗎？ |
| 參數 | 每一個閾值（例如 `--maf 0.01`）我知道理由嗎？ |
| 欄位 | 它用的欄位編號或名稱，和我的檔案一致嗎？ |
| 覆寫 | 會不會覆寫或刪除原始檔？ |
| 輸出 | 輸出檔名清楚嗎？會不會蓋掉上一步的結果？ |
| 驗證 | 有沒有印出可以讓我對照的數字？ |

不懂的地方直接問 AI：「`--hwe 1e-6` 是什麼意思？為什麼是這個值？有沒有文獻依據？」然後把它提到的文獻查出原文確認。

## 練習

??? question "下面這段 AI 寫的程式有什麼問題？"

    ```bash
    plink --bfile data/mydata --maf 0.01 --make-bed --out data/mydata
    ```

??? success "查看答案"

    `--out data/mydata` 與輸入檔同名，會**覆寫原始資料**。應改成輸出到 `results/`，例如 `--out results/mydata_maf01`。
