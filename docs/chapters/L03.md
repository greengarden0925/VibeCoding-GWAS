# L03 與 AI 協作的工作流程：規劃、下指令、驗證

## 學習目標

- 用「先規劃、再寫程式、最後驗證」三段式流程完成分析任務。
- 寫出包含背景、輸入、輸出、限制、驗證方式的提示詞。
- 建立專案說明檔，讓 AI 每次開啟專案都知道規則。

## 時間配置

| 段落 | 時間 | 內容 |
|---|---|---|
| 觀念 | 15 分鐘 | 三段式流程、好提示詞的五個元素 |
| 實作 | 30 分鐘 | 用練習資料完成一個小任務 |
| 討論 | 15 分鐘 | 比較同學們拿到的不同程式碼 |

## 1. 三段式流程

```text
規劃（AI 說明要怎麼做，你確認） → 寫程式（一次只做一小步） → 驗證（對照已知答案）
```

**規劃：** 不要一開始就叫 AI 寫完整流程。先請它列出步驟，你檢查每一步是否合理，再開始寫。

**一次一小步：** 一個腳本只做一件事，例如「計算缺失率」。小步驟容易驗證，也容易找出錯在哪。

**驗證：** 每一步都要有你能判斷對錯的依據，例如樣本數、已知的數值、與教學文件的輸出比較。

## 2. 好提示詞的五個元素

| 元素 | 說明 | 例子 |
|---|---|---|
| 背景 | 你是誰、在做什麼研究 | 「我在做病例對照 GWAS，資料是 PLINK bed 格式」 |
| 輸入 | 檔案在哪、長什麼樣子 | 「`data/sample.fam` 第 6 欄是表現型，1 是對照、2 是病例」 |
| 輸出 | 要產出什麼檔案、什麼格式 | 「輸出 `results/pheno_summary.tsv`，欄位為 group、n」 |
| 限制 | 不能做的事、要用的工具 | 「只用 Python 標準函式庫，不要刪除任何原始檔」 |
| 驗證 | 你要怎麼確認它是對的 | 「請在最後印出總人數，讓我和 `wc -l` 的結果對照」 |

## 3. 範例：好提示詞與壞提示詞

壞的提示詞：

```text
幫我做 GWAS 的 QC。
```

AI 必須自己猜閾值、猜檔案位置、猜要輸出什麼，結果很難驗證。

好的提示詞：

```text
背景：我在做病例對照 GWAS 的品質控制，使用 PLINK 1.9。
輸入：data/1KG.EAS.auto.snp.norm.nodup.split.rare002.common015.missing（bed/bim/fam 三個檔案）。
任務：只做一件事，計算每個樣本與每個變異的缺失率。
輸出：結果放在 results/ 資料夾，檔名前綴 plink_results。
限制：先把要執行的完整指令列給我看，我確認後再執行。
驗證：執行後告訴我 .imiss 和 .lmiss 各有幾列，以及 F_MISS 最大值。
```

## 4. 專案說明檔

Claude Code 每次開啟新對話時都會讀取專案資料夾裡的 `CLAUDE.md`，作為這個專案的固定指示（[How Claude remembers your project](https://code.claude.com/docs/en/memory)）。官方文件也提醒，這些內容是給 AI 的背景資訊，不是強制設定，所以重要的保護（例如不刪原始資料）仍要靠你自己檢查。其他 AI 工具也有類似機制，例如 `AGENTS.md`。建議在 `~/vibegwas/CLAUDE.md` 寫入：

```markdown
# 專案規則
- 這是 GWAS 課程練習專案，資料是 1000 Genomes 公開資料。
- 原始資料放在 data/，絕對不要修改或刪除 data/ 裡的檔案。
- 每個步驟寫成一個獨立腳本，放在 scripts/，檔名以步驟編號開頭（例如 01_missing.sh）。
- 結果放 results/，圖放 figures/。
- 執行任何會刪除或覆寫檔案的指令前，先詢問我。
- 每一步結束時，回報樣本數與變異數的變化。
```

## 5. 實作：讀懂 .fam 檔

下載練習資料前，先用一個假的小檔案練習。請 AI 建立 `data/toy.fam`，然後完成任務：

```text
請在 data/ 建立一個叫 toy.fam 的練習檔，10 列，PLINK fam 格式（6 欄，空白分隔），
第 6 欄表現型隨機填 1 或 2。
然後寫一個 Python 腳本 scripts/00_count_pheno.py，讀取 fam 檔，
輸出病例數（2）與對照數（1）。最後用一行 awk 指令算一次給我對照。
```

??? success "查看答案"

    驗證方式：Python 腳本算出的病例數加對照數應該等於 10，而且要和下面這行 awk 的結果相同：

    ```bash
    awk '{print $6}' data/toy.fam | sort | uniq -c
    ```

    如果兩者不同，請 AI 解釋差異。常見錯誤是把第 5 欄（性別）當成表現型。

## 6. 當 AI 出錯時

1. 把**完整**錯誤訊息貼給 AI。
2. 請它先「解釋錯誤原因」，不要直接改。
3. 判斷原因是否合理，再讓它修改。
4. 修改後重新執行，並重做驗證。

## 驗證清單

- [ ] 我寫的提示詞包含背景、輸入、輸出、限制、驗證五個元素。
- [ ] 專案資料夾裡有 `CLAUDE.md`。
- [ ] Python 腳本與 awk 指令算出的病例、對照人數一致。
